# 네이버 카페 통계도구로 작성자 실제 로그인 아이디 추출 (조사 기록)

> 상태: **검증 완료 · 미구현**. 나중에 필요할 때 이 문서를 근거로 구현.
> 조사일: 2026-08-07 (김해줌마 cafe_id=21031223, 7월 데이터 기준)

## 핵심 발견

네이버 카페 **통계도구(멤버 순위)** API는 회원의 **마스킹되지 않은 전체 로그인 아이디**를
반환한다. 이것이 전체 아이디를 대량으로 얻는 **유일한** 방법이다.

| 소스 | 딸랑해 아이디 | 비고 |
|---|---|---|
| 스탭 회원검색 (`search_members`, ManageMemberListViewAjax) | `lmh2****` | 마스킹됨 ❌ |
| **통계도구 API** (`cafe.stat.naver.com`) | `lmh2022` | 전체 ✅ |

## API 사용법

이미 `src/cafe_api.py`에 구현되어 있음 (통계 연동 커밋 f1126a9):

- `fetch_member_stat(cafe_id, year_month, key, client)` — 단일 지표 월간 순위
- `fetch_member_stats_all(cafe_id, year_month, client)` — 6지표 병합, `{user_id: {...}}`

엔드포인트:
```
GET https://cafe.stat.naver.com/api/cafe/{cafeId}/rank/{metric}
    ?service=CAFE&timeDimension=MONTH&startDate=YYYY-MM-01
    &memberId=멤버&exclude=member,board,dashBoard
Referer: https://cafe.stat.naver.com/cafe/{cafeId}/rank/member
```
지표(metric): `memberCreate`(작성글수) `memberComment`(댓글수) `memberLike`(보낸♥)
`memberLiked`(받은♥) `memberCv`(조회수) `memberVisit`(방문수)

응답 구조 — 순위 행은 `columnInfo`가 아니라 `rows`에 있음:
```
result.statData[0].data.rows = {
  v:   ["2r3LQ", ...],       # 통계 내부 멤버코드(idNo와 동일)
  cnt: [311, 308, ...],      # 카운트
  rank:[1, 2, ...],
  memberInfos: [[             # ★ 여기에 실제 아이디
    {userId:"lmh2022", nickName:"딸랑해", memberLevelName:"명예렐라",
     joinDate:"2020.05.30.", idNo:"2r3LQ"}, ...
  ]]
}
```

## 두 가지 제약 (구현 시 반드시 고려)

### 1. 상위 랭커만 나온다
랭킹 API라 카페별 **월간 상위 ~99명**(지표별 top30의 합집합)만 반환.
1회성·가끔 작성자는 순위에 안 들어와 아이디를 못 얻는다.
→ 단, **과거 월도 조회 가능**하므로 여러 달치를 당기면 그달그달 랭커가 달라져
   활동 회원 커버리지가 누적적으로 넓어진다.

### 2. 크롤 데이터(member_key)와의 연결은 "닉네임"으로만 가능
- 통계의 `idNo`(`2r3LQ`, 짧은 코드)와 크롤의 `member_key`
  (`Fk1DYBg6wW8-Q4l6I8IuvU3QPHWmMvvwxIMhGMlq5yY`, 43자 해시)는 **다른 식별자 체계** →
  직접 조인 불가.
- 유일한 연결고리는 **닉네임**. 네이버 카페 닉네임은 카페 내 고유라 신뢰도가 높다.

실측 (김해 7월):
- 통계 99명 중 → **고유 매칭 70명**, 모호(닉 재사용) 1명, 크롤에 없음 28명
- 카페 전체 닉네임 4,407개 중 복수 member_key에 걸친 닉 101개(2.3%)뿐

## 구현 시 권장 설계 (미구현)

`member_identity(cafe_id, member_key, login_id, source, updated_at)` 테이블:
1. `fetch_member_stats_all`로 **여러 달치**를 당겨 `nickname → member_key`로 매핑,
   `login_id` 저장 (source='naver_stat')
2. 모호(복수 member_key)·미매칭 닉네임은 **기록하지 않음** (오염 방지)
3. 크롤 게시글·업체현황·서포터즈 화면에 실제 로그인 아이디 표시

→ 순위권 밖 1회성 작성자는 이 방법으로 못 얻음. 그건 스탭 검색으로 개별 해결
   해야 하나 그마저 마스킹(`lmh2****`)이라 완전한 아이디는 통계도구가 유일.
